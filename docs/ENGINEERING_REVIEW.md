# Engineering review

Reviewed on October 13, 2026. This is a source review and isolated demo verification, not a production penetration test or a complete Git-history secret scan.

## Exposure and access control

Browser-visible API URLs are expected. Jira credentials, the Supabase service-role key, and the OpenAI key belong exclusively on the server. The inspected frontend does not import those server clients. A secret being absent from the browser does **not** make an unauthenticated API safe.

| Priority | Finding | Evidence and required work |
| --- | --- | --- |
| Critical for connected deployments | Administrative APIs have no application authentication or per-user authorization | `app/api/jira/connect-basic/route.ts`, `app/api/teams/route.ts`, `app/api/sync/route.ts`, and coaching mutations. Add verified identities and resource authorization before exposing a connected installation. CORS and hidden buttons are not authorization. |
| High | Jira connection is shared globally | `lib/jira-connections.ts` stores the connection under `default`. A visitor must not be able to replace another user's credentials. Introduce tenant ownership and enforce it for every read/write. |
| High | AI limits can be bypassed and database errors fail open | `lib/rate-limit.ts` combines a client-controlled session ID with an IP and performs read-then-write counters without atomicity. Use a server-owned identity, atomic counters, a shared budget, and explicit failure handling. |
| High | Schema bootstrap is destructive and does not establish tenant RLS | `supabase/schema.sql` drops tables. Replace production bootstrap with executable, tested migrations and explicit policies. Do not run the bootstrap on a live database. |
| High | Framework and dependency advisories remain | The installed lockfile's `npm audit --omit=dev` reported 12 affected packages: 1 critical, 9 high, 1 moderate, 1 low. Next.js 14.2.35 is affected. Applicability differs by runtime and features; this count is not proof of exploitation. A patched-framework upgrade and regression testing are required. |
| Medium | Internal error messages reach API responses | Multiple handlers return `Error.message` directly. Keep diagnostics in structured server logs and return stable, generic client errors. |
| Medium | Sync replacement is not atomic | `lib/sync.ts` can delete records before inserts complete. Use a transaction or staging/version switch so failures preserve the previous snapshot. |
| Medium | Forge path is a tenant-isolation spike | Validate configured audience and bind the verified Forge tenant to permitted teams before general availability. |

## Demo isolation implemented in this change

- `middleware.ts` routes API requests from demo sessions to an allowlisted fixture responder. Unknown endpoints and mutations fail closed.
- `STATUS_PILOT_DEMO_ONLY=1` locks a public portfolio deployment to fixtures, including requests without a demo cookie. Configure it at build and runtime and deploy without live credentials.
- Demo sessions use HTTP-only cookies and same-origin checks for switching. Demo and connected browser histories have separate keys.
- Deterministic sample analysis is explicitly labeled; no provider calls or costs are generated by the fixture responder.
- UI mutation controls are disabled in demo mode. This is a usability measure; the API rejection is the actual enforcement.

These changes isolate the demonstration. They do not fix connected-mode authentication, tenant isolation, or the dependency advisories above. A public GitHub repository and a publicly accessible connected deployment are separate decisions.

## Verification

The offline test suite covers read contracts, filtering, shared metrics, active-sprint semantics, mutation rejection, and deterministic operation without network calls. TypeScript and the production build were checked. An isolated HTTP/browser smoke test exercised demo entry, dashboards, coaching, reports, questions, mutation rejection, cross-origin rejection, and exit. Production credentials and live services were not used.
